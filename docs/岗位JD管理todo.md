# 岗位 JD 管理 Todo

当前岗位 JD 管理模块的核心流程已经具备。以下为后续增强项，不影响当前基本使用。

## 待完善功能

### 1. 操作日志详情展示

- 展示谁在什么时间执行了什么操作
- 记录 JD 修改前后的内容差异
- 记录发布、暂停、关闭、归档、恢复等状态变化
- 支持按操作人、操作类型和时间筛选

### 2. 批量操作结果明细

- 批量发布、暂停、归档后展示成功数量和失败数量
- 对失败 JD 显示具体原因
- 支持查看失败列表并重试
- 避免只显示统一的“操作完成”提示

### 3. JD 发布有效期配置

- 支持设置发布时间和截止时间
- 到期后自动变为“已过期”
- 已过期 JD 不允许继续投递
- 后台显示剩余有效天数
- 发布前可配置默认有效期

### 4. 归档恢复与彻底清理权限

- 归档 JD 默认进入回收区，不再出现在正常列表
- 支持恢复为归档前状态或恢复为草稿
- 彻底删除需要更高权限
- 彻底删除前展示关联投递、面试和收藏影响
- 物理删除操作需要二次确认并记录原因

### 5. 更细的管理员权限控制

- 超级管理员：拥有全部权限
- HR：管理 JD、候选人和投递流程
- 面试官：查看分配的面试和填写面试结果
- 只读人员：只能查看，不能修改或删除
- 限制不同角色的数据范围和操作范围

### 6. 大量 JD 时的后端异步导出

- 大批量导出由后端异步生成文件
- 前端显示生成进度
- 生成完成后提供下载链接
- 支持 CSV 和 JSON 格式
- 避免浏览器在大量数据导出时卡顿或超时

## 相关设计原则

- JD 业务状态与数据归档状态分开管理
- 岗位类别和招聘类型与单条 JD 固定关联
- 已有投递的 JD 不允许随意修改招聘类型
- 归档优先于物理删除
- 重要状态变更必须保留审计记录
